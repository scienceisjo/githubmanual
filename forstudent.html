준비된 예제 파일을 GitHub Pages에 올리면 누구나 열어 볼 수 있는 내 링크가 생기게 됩니다. 예제 파일 두 개를 직접 올려보면서, 직접 만든 파일을 올릴 때 막히는 곳까지 같이 짚어보겠습니다!

위쪽 탭이나 아래 ‘다음’ 버튼으로 한 단계씩 따라와주세요. 사진 속 빨간 네모와 번호가 누를 곳이고, 사진 아래에 같은 번호로 설명을 적어두었습니다. 사진을 누르면 크게 볼 수 있습니다.

https://hnrscience.github.io/my-first-web/hello.html

저장소 이름은 2단계에서 정합니다.
파일 이름은 3·6단계에서 올린 파일입니다. 이름이 index.html 이면 생략해도 열립니다.

단계마다 이 주소를 한 조각씩 만들어 가게 됩니다. 그리고 4단계(Pages)에서 이 주소를 실제로 켜게 됩니다.

영어 화면 그대로 따라해주세요

GitHub 화면은 영어로 되어 있습니다. 크롬이 “이 페이지를 번역할까요?” 하고 물어보면 번역하지 말아주세요. 번역하면 버튼 이름이 사진과 달라져서 오히려 더 헷갈리게 됩니다.

누르는 버튼은 몇 개 되지 않고, 앞으로 파일을 올릴 때도 같은 버튼을 계속 누르게 됩니다. 그래서 처음부터 영어 이름으로 익혀두시는 편이 훨씬 편합니다. 아래 단어만 알아두시면 충분합니다^^

GitHub 가입하기

내 이름으로 된 GitHub 공간을 만들어보겠습니다! 여기서 정한 아이디가 주소 맨 앞 아이디.github.io 가 됩니다.

  • 주소창에 github.com 을 입력해 들어간 뒤, 오른쪽 위 Sign up 을 눌러주세요.
  • 개인 구글 아이디가 있다면 구글로 가입해주세요. Continue with Google 을 누르고 내 구글 계정을 고르면 이메일이 자동으로 채워지게 됩니다. 다른 계정으로 가입하시려면 Use a different Google account 를 눌러주세요.
  • 아래 사진처럼 Username 과 Country/Region 을 확인하고 Create account 를 눌러주세요.
  • ‘사람인지 확인’하는 퍼즐이 나오면 풀어주세요. 메일로 온 인증 코드(숫자)를 넣으라고 하면 메일함에서 확인해 넣어주세요!^^
구글 아이디가 없다면
가입 화면에서 Email 을 입력하고 Continue 를 누른 뒤, 영어와 숫자를 섞어 Password 를 만들고 다시 Continue 를 누릅니다. 그다음 Username 을 정하는 순서로 진행됩니다.
사용자 이름(Username)은 신중하게 정해주세요
가입할 때 정한 Username 이 곧 내 사이트 주소가 됩니다. 예를 들어 아이디가 hnrscience 라면 내 주소는 hnrscience.github.io/... 로 시작하게 됩니다. 기억하기 쉬운 것으로 정하시고 꼭 적어두세요! (5단계에서 다시 씁니다.)

새 저장소(Repository) 만들기

파일을 넣어둘 방(저장소)을 만들어보겠습니다! 저장소 이름이 주소 가운데 /저장소이름/ 이 됩니다. 보통 사이트(작품) 하나에 저장소 하나씩 만듭니다.

① ‘새 저장소’ 화면 열기

여는 방법이 세 가지 있습니다. 편한 방법 하나만 골라 해주세요.

방법 1오른쪽 위 + → New repository
방법 2왼쪽 위 ☰ → Repositories → New repository
방법 3주소창에 바로 입력
주소창에 github.com/new 를 그대로 입력해주세요. 버튼을 찾지 않아도 아래 Create a new repository 화면이 바로 열립니다. 1단계 마지막 사진의 초록색 Create repository 를 눌러도 같은 화면이 나옵니다.
② 이름 정하고 만들기
궁금하면 열기Description · README · .gitignore · license 는 무엇이고, 왜 건드리지 않나요?
Owner 는 저장소 주인입니다. 내 아이디가 자동으로 들어가 있습니다.
Description 은 저장소를 한 줄로 소개하는 칸입니다. 비워두셔도 되고, 나중에 저장소 첫 화면 오른쪽 About 옆 톱니바퀴에서 언제든 적을 수 있습니다.
Add README 를 켜면 저장소 설명서 파일(README.md)이 자동으로 만들어집니다. 그러면 저장소가 빈 채로 시작하지 않아서, 3단계에서 쓰는 Quick setup 화면(creating a new file 링크)이 나오지 않고 사진과 화면이 달라지게 됩니다. 그래서 끈 채(Off)로 시작합니다. 혹시 켜셨더라도 문제가 생기는 것은 아니니, 3단계에서 Add file 의 Create new file 로 똑같이 진행해주세요.
Add .gitignore 는 프로그래머가 Git 명령어로 컴퓨터 폴더를 통째로 올릴 때 “이 파일들은 빼고 올려줘” 하고 적어두는 목록입니다. 웹 화면에서 파일을 직접 올리는 우리 방식에서는 쓸 일이 없습니다.
Add license 는 다른 사람이 내 코드를 가져다 써도 되는지 정하는 이용 규칙(MIT 등)입니다. 고르지 않으면 기본 저작권이 적용되어서, 공개 저장소라 누구나 볼 수는 있지만 마음대로 가져다 쓸 권리는 없습니다. 연습할 때는 필요 없고, 필요해지면 나중에 추가할 수 있습니다.
정리하면 오늘은 이름과 Public 두 가지만 확인하시면 충분합니다.
Create repository 버튼이 눌리지 않을 때
대부분 Repository name 을 적지 않았거나, 이름에 띄어쓰기나 한글이 들어간 경우입니다. 영어 이름을 적고 초록 ✔ 가 뜨는지 확인해주세요.
알아두기
여기서 정한 저장소 이름도 내 주소에 들어가게 됩니다. 주소는 (아이디).github.io/저장소이름/ 모양이 됩니다.

② creating a new file 누르기

저장소를 막 만들면 아래처럼 Quick setup(빠른 시작) 화면이 나옵니다. 빈 저장소에 처음 들어왔을 때만 보이는 안내 화면입니다. 파란 상자 안의 작은 파란 글씨를 찾아주세요. 그 아래 회색 상자의 명령어들(…on the command line)은 프로그래머가 쓰는 Git 명령어라서 신경 쓰지 않으셔도 됩니다.

바로 옆의 uploading an existing file 은요?
그것은 ‘파일 올리기’입니다. 두 번째 실습(6단계)에서 같은 기능을 Add file 의 Upload files 로 쓰게 됩니다. 지금은 creating a new file 만 눌러주세요.
③ 이름 적고, 붙여넣고, Commit
Commit 은 무슨 뜻인가요?
‘이대로 저장을 확정한다’는 뜻입니다. GitHub 에서는 저장 버튼 이름이 Commit changes 입니다. 앞으로 파일을 고칠 때도 늘 이 버튼으로 마무리하게 됩니다.
④ 올라갔는지 확인하기
⑤ 왜 꼭 index.html 일까요?

주소창에 www.naver.com 처럼 파일 이름 없이 쳐도 페이지가 열립니다. 웹사이트는 주소가 폴더(/)에서 끝나면, 그 폴더 안에서 미리 약속된 대표 파일을 알아서 찾아 보여주기 때문입니다. GitHub Pages 에서는 그 대표 파일의 이름이 index.html 입니다. (index 는 ‘목차’라는 뜻으로, 폴더의 첫 화면 역할을 한다는 의미입니다.)

…/my-first-web/→📄 index.html 이 자동으로 열립니다
…/my-first-web/hello.html→📄 hello.html 은 이름을 불러야 열립니다
…/my-first-web/→index.html 이 없으면 404 (없음)

그래서 대표 페이지를 index.html 로 두면 학생들에게 짧은 주소만 알려줘도 바로 열립니다. 주소가 짧을수록 받아 적거나 QR 로 만들 때 실수도 줄어듭니다.

지금 보고 계신 이 매뉴얼이 실제 예입니다. 이 매뉴얼 저장소에는 index.html 이 없고 forstudent.html 만 있습니다. 직접 눌러보세요!
✓ scienceisjo.github.io/githubmanual/forstudent.html 은 열립니다.
✕ scienceisjo.github.io/githubmanual/ 처럼 끝의 파일 이름을 빼면 404 가 뜹니다.
여기까지 하셨다면
저장소 첫 화면에 index.html 이 보이실 겁니다. 이제 공개 스위치만 켜면 됩니다.

GitHub Pages 켜기

저장소를 웹사이트로 공개하는 스위치를 켜보겠습니다! 저장소는 원래 파일을 보관만 하는 곳이고, Pages 를 켜야 GitHub 이 그 파일을 누구나 열 수 있는 웹사이트로 공개해줍니다.

파일을 올렸다고 끝난 것이 아닙니다. 인터넷에 공개하는 스위치를 켜야 링크가 생깁니다. 사진의 번호 순서대로 눌러주세요.

궁금하면 열기Deploy from a branch · main · / (root) 는 무슨 뜻인가요?
Deploy from a branch 는 “저장소에 있는 파일을 그대로 사이트로 내보내줘”라는 뜻입니다. 다른 선택지인 GitHub Actions 는 프로그램으로 사이트를 조립하는 고급 방식이라 쓸 일이 없습니다.
Branch(브랜치) 는 저장소 안의 ‘버전 줄기’입니다. 처음에는 main 하나뿐이고, 3단계에서 Commit 한 파일이 바로 여기에 들어 있습니다.
/ (root) 는 저장소의 맨 바깥 폴더(첫 화면)를 말합니다. 다른 선택지인 /docs 는 docs 라는 폴더 안의 파일만 공개하는 방식입니다.
세 가지를 합치면 “main 줄기의 첫 화면에 있는 파일을 웹사이트로 공개해줘”라는 뜻이 됩니다. 그래서 파일을 폴더 속에 넣어 올리면 주소가 달라지게 됩니다.
Settings 가 두 군데라 헷갈릴 때
GitHub 에는 내 프로필 설정과 저장소 설정, 두 군데에 Settings 가 있습니다. 화면 왼쪽 위에 아이디 / 저장소이름 이 보이는 화면에서, 탭 줄에 있는 Settings 를 눌러야 Pages 메뉴가 나옵니다.
Save 를 눌러도 링크가 바로 뜨지 않습니다
정상입니다. GitHub 이 사이트를 ‘짓는’ 데 1~2분 정도 걸립니다. 다음 단계에서 기다렸다가 확인해보겠습니다.

기다렸다가 내 링크 열기

GitHub 이 저장소의 파일을 웹사이트로 내보내는 작업(배포, deploy)이 끝나길 기다렸다가, 생긴 링크를 열어보겠습니다!

먼저 1~2분 기다려주세요
Save 를 누른 직후에는 링크가 아직 없습니다. 보통 1~2분, 가끔은 3~5분까지 걸립니다. “링크가 없네?” 하고 포기하지 마시고 조금만 기다려주세요^^
① 기다리는 동안 짓는 중인지 확인하기

다 지어지면 아래처럼 주황 점이 초록 ✓ 로 바뀌게 됩니다.

② 링크 확인하기

초록 ✓ 가 되면 다시 Settings 의 Pages 로 가주세요. 이미 열려 있다면 F5 로 새로고침해주세요. 화면 위쪽에 Your site is live at 상자가 생기게 됩니다.

③ 내 주소 미리 만들어보기

아이디와 저장소 이름을 넣으면 내 주소가 만들어집니다. 눌러서 바로 열어볼 수도 있습니다.

첫 링크가 열렸다면
3단계에서 본 축하 화면이 보이실 겁니다. 주소 끝에 아무것도 붙이지 않았는데도 열린 것은 파일 이름이 index.html 이기 때문입니다. 이름이 다른 파일은 어떻게 되는지 다음 단계에서 직접 해보겠습니다.

두 번째 실습 · 내 파일 올리기 Upload files

이름이 index.html 이 아닌 파일을 올리고, 그 파일의 주소를 찾아 들어가보겠습니다! 직접 만든 파일을 올릴 때 가장 많이 막히는 부분입니다.

AI 로 만들었거나 다운로드한 파일은 이름이 index.html 이 아닌 경우가 대부분입니다. 그래서 이번에는 이름이 hello.html 인 파일을 이름 그대로 올려보겠습니다.

index.html은 주소만 쳐도 열립니다

직접 만든 파일을 올릴 때 이것만 지켜주세요
  1. 이름을 바꾸지 말고 그대로 올려주세요. 이름을 바꾸다가 .html.html 이 되는 실수가 가장 흔합니다.
  2. 주소 끝에 /파일이름.html 을 붙여주세요. 예를 들면 .../my-first-web/quiz.html 입니다.
  3. 파일 이름은 처음부터 띄어쓰기 없는 영어로 정해주세요. AI 에게 만들어 달라고 할 때 “quiz.html 처럼 영어 이름으로 저장할 수 있게 해줘”라고 같이 부탁하면 편합니다.
  4. 대소문자까지 똑같이 적어주세요. Quiz.html 과 quiz.html 은 서로 다른 파일입니다.

파일 이름을 바꿀 때 가장 많이 하는 실수, ‘이중 확장자’ 함정

다운로드한 파일은 이미 .html 파일입니다 (예: myapp.html). 그런데 윈도우는 보통 .html 을 숨겨서 화면에는 myapp 만 보여줍니다.

이 상태에서 이름 바꾸기로 index.html 이라고 통째로 입력하면 어떻게 될까요?

화면에는 index.html→진짜 이름은 index.html.html

숨겨진 .html 뒤에 .html 이 한 번 더 붙어서, 사이트가 파일을 찾지 못하고 404 가 뜨게 됩니다.

올바른 방법
  • 먼저 확장자가 보이도록 켜주세요. 윈도우 탐색기 위쪽 보기 메뉴의 표시에서 파일 확장명에 체크하면 됩니다. (맥은 Finder 설정의 고급에서 ‘모든 파일 확장자 보기’를 켭니다.)
  • 이제 myapp.html 처럼 .html 이 보이게 됩니다.
  • 오른쪽 클릭으로 이름 바꾸기를 누르고, 앞의 myapp 만 지운 뒤 index 로 바꿔주세요. 점(.html)은 건드리지 말아주세요.
  • 진짜 이름이 정확히 index.html(점이 1개)인지 확인해주세요.
이렇게 되어야 합니다 (점 하나)

index.html.html (점이 둘)index.html.txt (끝이 .txt)index (.html 이 없음)

내가 만든 코드가 HTML 이 아닐 때

올렸는데 화면이 이상하거나, 코드 글자만 보이거나, 열리지 않는다면 그 코드가 ‘HTML 한 파일’이 아닐 수 있습니다. GitHub Pages 는 HTML 파일만 웹페이지로 보여줍니다. 코드 맨 윗줄을 먼저 확인해주세요.

이렇게 시작하면 괜찮습니다
<!DOCTYPE html><html lang="ko">
이렇게 시작하면 아직 HTML 이 아닙니다
import React from "react"function App() { ... }def main(): (파이썬)```jsx / ```python

아래 마법의 문장을 복사해서 AI 채팅에 붙여넣으면 HTML 한 파일로 다시 만들어줍니다. 그 코드로 3단계(Create new file)나 6단계(Upload files)를 똑같이 진행해주세요.

AI 에 붙여넣기 지금 만든 걸 HTML 파일 하나로 다시 만들어줘. HTML, CSS, JavaScript를 전부 한 파일에 넣고, 맨 윗줄은 <!DOCTYPE html> 으로 시작하게 해줘. 다른 파일 없이 이 파일 하나만으로 작동해야 해. 파일 이름은 띄어쓰기 없는 영어로 정해줘.
