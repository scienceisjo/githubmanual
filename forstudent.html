GitHub으로
인터넷에 올리기.

준비된 예제 코드를 GitHub Pages에 올리면, 누구나 열어 볼 수 있는 내 링크가 생겨요. 두 번 연습하면 내가 만든 파일도 혼자 올릴 수 있어요.

위쪽 탭이나 아래 ‘다음’ 버튼으로 한 단계씩 따라오세요. 사진 속 빨간 네모와 번호가 누를 곳이고, 사진 아래에 같은 번호로 설명이 있어요. 사진을 누르면 크게 보여요.
완성하면 이런 주소가 생겨요
https://hnrscience.github.io/my-first-web/hello.html
아이디 — 1단계 가입 때 정해요
저장소 이름 — 2단계에서 정해요
파일 이름 — 3·6단계에서 올린 파일. index.html 이면 생략할 수 있어요

단계마다 이 주소를 한 조각씩 만들어 가요. 그리고 4단계(Pages)에서 이 주소를 실제로 켜요.

영어 화면 그대로 따라 하세요

GitHub 화면은 영어예요. 크롬이 “이 페이지를 번역할까요?” 하고 물으면 번역하지 마세요. 번역하면 버튼 이름이 사진과 달라져서 오히려 헷갈려요.

누르는 버튼은 몇 개 안 되고, 앞으로 파일을 올릴 때도 같은 버튼을 계속 누르게 돼요. 처음부터 영어 이름으로 익혀 두시는 게 훨씬 편합니다. 아래 단어만 알면 충분해요.

GitHub 가입하기

내 이름으로 된 GitHub 공간을 만드는 단계예요. 여기서 정한 아이디가 주소 맨 앞 아이디.github.io 가 됩니다.

  • 주소창에 github.com 을 입력해 접속 → 오른쪽 위 Sign up 클릭.
  • 개인 구글 아이디가 있다면 구글로 가입하세요. Continue with Google 을 누르고 내 구글 계정을 고르면 이메일이 자동으로 채워져요. 다른 계정으로 하려면 Use a different Google account.
  • 아래 사진처럼 Username·Country/Region 을 확인하고 Create account.
  • ‘사람인지 확인’ 퍼즐이 나오면 풀고, 메일로 온 인증 코드(숫자)를 넣으라고 하면 메일함에서 확인해 넣어 주세요.
구글 아이디가 없다면
가입 화면에서 Email 입력 → Continue → Password 만들기(영어+숫자 섞어서) → Continue → Username 정하기 순서로 진행하면 돼요.
사용자 이름(Username)은 신중하게
가입할 때 정한 Username 이 곧 내 사이트 주소가 돼요. 예) 아이디가 hnrscience 면 → 내 주소는 hnrscience.github.io/... 로 시작해요. 기억하기 쉬운 걸로 정하고 적어 두세요 (5단계에서 씁니다).
연수장에서 가입이 막히면
같은 와이파이로 여러 분이 한꺼번에 가입하면 막힐 수 있어요. 그럴 땐 휴대폰 핫스팟으로 가입해 보세요.

새 저장소(Repository) 만들기

파일을 넣어 둘 방(저장소)을 만드는 단계예요. 저장소 이름이 주소 가운데 /저장소이름/ 이 됩니다. 보통 사이트(작품) 하나 = 저장소 하나로 만들어요.

① ‘새 저장소’ 화면 열기

방법이 세 가지예요. 편한 것 하나만 하면 돼요.

방법 1오른쪽 위 + → New repository
방법 2왼쪽 위 ☰ → Repositories → New repository
방법 3주소창에 바로 입력
주소창에 github.com/new 를 그대로 입력하세요. 버튼을 찾지 않아도 아래 Create a new repository 화면이 바로 열려요. (1단계 마지막 사진의 초록 Create repository 를 눌러도 같아요.)
② 이름 정하고 만들기
궁금하면 열기Description · README · .gitignore · license 는 뭔가요? 왜 안 건드려요?
Owner — 저장소 주인. 내 아이디가 자동으로 들어가 있어요.
Description — 저장소 한 줄 소개예요. 비워도 되고, 나중에 저장소 첫 화면 오른쪽 About 옆 톱니바퀴에서 언제든 적을 수 있어요.
Add README — 저장소 설명서 파일(README.md)을 자동으로 만들어 줘요. 켜면 저장소가 빈 채로 시작하지 않아서, 3단계에서 쓰는 Quick setup 화면(creating a new file 링크)이 안 나오고 사진과 화면이 달라져요. 그래서 끄고(Off) 시작해요. 켰더라도 고장은 아니에요 — 3단계에서 Add file → Create new file 로 똑같이 하면 돼요.
Add .gitignore — 프로그래머가 Git 명령어로 컴퓨터 폴더를 통째로 올릴 때 “이 파일들은 빼고 올려” 하고 적어 두는 목록이에요. 웹 화면에서 파일을 직접 올리는 우리 방식에는 쓸 일이 없어요.
Add license — 다른 사람이 내 코드를 가져다 써도 되는지 정하는 이용 규칙(MIT 등)이에요. 안 고르면 기본 저작권이 적용돼서, 공개 저장소라 누구나 볼 수는 있지만 마음대로 가져다 쓸 권리는 없어요. 연습용엔 필요 없고, 필요해지면 나중에 추가할 수 있어요.
결론: 오늘은 이름과 Public 두 가지만 확인하면 충분해요.
Create repository 버튼이 안 눌려요
거의 다 Repository name 을 안 적었거나, 이름에 띄어쓰기·한글이 들어가서예요. 영어 이름을 적고 초록 ✔ 가 뜨는지 보세요.
알아두기
여기서 정한 저장소 이름도 내 주소에 들어가요 → (아이디).github.io/저장소이름/

첫 파일 만들기 creating a new file

만든 방에 첫 웹페이지 파일을 넣는 단계예요. 이름을 꼭 index.html 로 하는 이유는 이 단계 맨 아래에 정리했어요.

첫 실습은 GitHub 안에서 새 파일을 만들고 코드를 붙여넣는 방법이에요. 파일 이름을 내가 직접 타이핑하니까 실수가 거의 없어요.

① 예제 코드 복사하기

아래 복사 버튼을 누르세요. 열면 축하 메시지만 뜨는 아주 짧은 페이지예요.

index.html 
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">

<body>

</body>
</html>

② creating a new file 누르기

저장소를 막 만들면 아래처럼 Quick setup(빠른 시작) 화면이 나와요. 빈 저장소에 처음 들어왔을 때만 보이는 안내 화면이에요. 파란 상자 안의 작은 파란 글씨를 찾으세요. 그 아래 회색 상자의 명령어들(…on the command line)은 프로그래머가 쓰는 Git 명령어라서 무시해도 돼요.

바로 옆 uploading an existing file 은?
그건 ‘파일 올리기’예요. 두 번째 실습(6단계)에서 같은 기능을 Add file → Upload files 로 씁니다. 지금은 creating a new file 만 누르세요.
③ 이름 적고, 붙여넣고, Commit
Commit 이 뭐예요?
‘이대로 저장 확정’이라는 뜻이에요. GitHub 에서는 저장 버튼 이름이 Commit changes 예요. 앞으로도 파일을 바꾸면 늘 이 버튼으로 끝나요.
④ 올라갔는지 확인
⑤ 왜 꼭 index.html 일까요?

주소창에 www.naver.com 처럼 파일 이름 없이 쳐도 페이지가 열리죠? 웹사이트는 주소가 폴더(/)에서 끝나면, 그 폴더 안에서 미리 약속된 대표 파일을 알아서 찾아 보여 줘요. GitHub Pages 에서 그 대표 파일의 이름이 index.html 이에요. (index 는 ‘목차’라는 뜻 — 폴더의 첫 화면 역할을 한다는 의미예요.)

…/my-first-web/→📄 index.html 이 자동으로 열려요
…/my-first-web/hello.html→📄 hello.html — 이름을 불러야 열려요
…/my-first-web/→index.html 이 없으면 404 (없음)

그래서 대표 페이지를 index.html 로 두면 학생들에게 짧은 주소만 알려 줘도 바로 열려요. 주소가 짧을수록 받아 적거나 QR 로 만들 때 실수도 줄어요.

지금 보고 계신 이 매뉴얼이 실제 예예요. 이 매뉴얼 저장소에는 index.html 이 없고 forstudent.html 만 있어요. 직접 눌러 보세요.
✓ scienceisjo.github.io/githubmanual/forstudent.html → 열려요
✕ scienceisjo.github.io/githubmanual/ → 404 (끝의 파일 이름을 빼면)
여기까지 했으면
저장소 첫 화면에 index.html 이 보일 거예요. 이제 공개 스위치만 켜면 돼요.

GitHub Pages 켜기

저장소는 원래 파일을 보관만 하는 곳이에요. Pages 를 켜면 GitHub 이 그 파일을 누구나 열 수 있는 웹사이트로 공개해 줘요.

파일을 올렸다고 끝이 아니에요. 인터넷에 공개하는 스위치를 켜야 링크가 생겨요. 사진의 번호 순서대로 누르세요.

궁금하면 열기Deploy from a branch · main · / (root) 는 무슨 뜻이에요?
Deploy from a branch — “저장소에 있는 파일을 그대로 사이트로 내보내 줘”라는 뜻이에요. 다른 선택지(GitHub Actions)는 프로그램으로 사이트를 조립하는 고급 방식이라 쓸 일이 없어요.
Branch(브랜치)와 main — 브랜치는 저장소 안의 ‘버전 줄기’예요. 처음엔 main 하나뿐이고, 3단계에서 Commit 한 파일이 바로 여기 들어 있어요.
/ (root) — 저장소의 맨 바깥 폴더(첫 화면)예요. 다른 선택지 /docs 는 docs 라는 폴더 안의 파일만 공개하는 방식이에요.
합치면 “main 줄기의 첫 화면에 있는 파일을 웹사이트로 공개해 줘”예요. 그래서 파일을 폴더 속에 넣어 올리면 주소가 달라져요.
Settings 가 두 군데라 헷갈려요
GitHub 엔 Settings 가 ① 내 프로필 설정, ② 저장소 설정 두 군데 있어요. 화면 왼쪽 위에 아이디 / 저장소이름 이 보이는 화면의 탭 줄에 있는 Settings 를 눌러야 Pages 메뉴가 나와요.
Save 를 눌러도 링크가 바로 안 떠요
정상이에요. GitHub 이 사이트를 ‘짓는’ 데 1~2분 걸려요. 다음 단계에서 기다렸다가 확인합니다.

기다렸다가 내 링크 열기

GitHub 이 저장소의 파일을 웹사이트로 내보내는 작업(배포, deploy)이 끝나길 기다렸다가, 생긴 링크를 여는 단계예요.

먼저, 1~2분 기다리기
Save 를 누른 직후엔 링크가 아직 없어요. 보통 1~2분(가끔 3~5분) 걸려요. “링크가 없네?” 하고 포기하지 마세요.
① 기다리는 동안 — 짓는 중인지 보기
② 링크 확인하기
  • 초록 ✓ 가 되면 다시 Settings → Pages 로 가요. (이미 열려 있으면 F5 로 새로고침)
  • 화면 위쪽에 아래처럼 Your site is live at 상자가 생겨요.
  • Visit site 를 누르면 내 사이트가 열려요. 그 주소가 바로 내 링크예요.
Settings → Pages 화면 위쪽에 생기는 상자
Your site is live at
https://(아이디).github.io/(저장소이름)/ Visit site
③ 내 주소 미리 만들어 보기

아이디와 저장소 이름을 넣으면 내 주소가 만들어져요. 눌러서 바로 열어 볼 수도 있어요.

첫 링크가 열렸다면
3단계의 축하 화면이 보일 거예요. 주소 끝에 아무것도 안 붙였는데 열린 건 파일 이름이 index.html 이라서예요. 이름이 다른 파일은 어떻게 되는지 다음 단계에서 직접 해 봅니다.

두 번째 실습 — 내 파일 올리기 Upload files

직접 만든 파일을 올릴 때 가장 많이 막히는 곳 — 이름이 index.html 이 아닌 파일의 주소 찾기를 미리 겪어 보는 단계예요.

이제 직접 만든 파일을 올리는 상황을 연습해요. AI로 만들었거나 다운로드한 파일은 이름이 index.html 이 아닌 경우가 대부분이에요. 이번엔 이름이 hello.html 인 파일을 이름 그대로 올리고, 그 파일의 링크를 찾아 들어가 봅니다.

index.html→ 주소만 쳐도 열려요
hello.html→ 주소 끝에 /hello.html 을 붙여야 열려요
① 연습 파일 내려받기

아래 다운로드 버튼을 누르면 다운로드 폴더에 hello.html 이 저장돼요.

hello.html 
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>두 번째 파일</title>
  <style>
    body{margin:0;min-height:100vh;display:flex;
      flex-direction:column;align-items:center;justify-content:center;
      text-align:center;font-family:'Malgun Gothic',sans-serif;
      color:#1d1d1f;background:#f5f5f7;}
    h1{font-size:2rem;margin:0 0 14px;}
    p{font-size:1.2rem;margin:0;color:#555;}
    .emoji{font-size:4rem;margin-bottom:8px;}
    b{background:#fff;padding:2px 8px;border-radius:6px;}
  </style>
</head>
<body>
  <div class="emoji">📮</div>
  <h1>두 번째 파일도 열렸어요!</h1>
  <p>주소 맨 끝을 보세요 → <b>/hello.html</b></p>
</body>
</html>

직접 만든 파일을 올릴 때, 이것만 지키세요
  1. 이름을 바꾸지 말고 그대로 올리기. 이름 바꾸다 .html.html 이 되는 실수가 제일 흔해요.
  2. 주소 끝에 /파일이름.html 붙이기. 예) .../my-first-web/quiz.html
  3. 파일 이름은 처음부터 영어, 띄어쓰기 없이. AI에게 만들어 달라고 할 때 “quiz.html 처럼 영어 이름으로 저장할 수 있게” 같이 부탁하면 편해요.
  4. 대소문자까지 똑같이. Quiz.html 과 quiz.html 은 다른 파일이에요.
  5. 파일 맨 윗줄이 <!DOCTYPE html> 인지 확인. 아니면 ‘안 될 때’ 탭의 마법의 문장으로 HTML 한 파일로 다시 받으세요.

빠른 해결 제일 빠름
주소 끝에 진짜 파일 이름을 붙이기 — 6단계에서 연습한 방법이에요.
  • 저장소 첫 화면에서 올린 파일의 정확한 이름을 확인. 대소문자까지 똑같이! (예: game.html)
  • 내 링크 끝에 그 이름을 붙여서 접속 → https://(아이디).github.io/(저장소이름)/game.html
주소만으로 열리게 하기 한 번에 끝
이름을 index.html 로 만들기 — 그럼 주소 끝에 안 붙여도 열려요.
  • 가장 안전한 방법: 저장소에서 Add file → Create new file → 이름 index.html → 코드 붙여넣기 → Commit changes. (3단계와 같아요)
  • 파일 이름을 컴퓨터에서 바꿔 올리려면 아래 ‘이중 확장자 함정’을 꼭 먼저 읽으세요.
  • 올린 뒤 1~2분 기다리고 링크 새로고침.

파일 이름을 바꿀 때 1등 실수 — ‘이중 확장자’ 함정

다운로드한 파일은 이미 .html 파일이에요 (예: myapp.html). 그런데 윈도우는 보통 .html 을 숨겨서 화면엔 myapp 만 보여 줘요.

이 상태에서 이름 바꾸기로 index.html 이라고 통째로 치면?

화면엔 index.html→진짜 이름은 index.html.html

숨겨진 .html 뒤에 또 .html 이 붙어 → 사이트가 파일을 못 찾아서 404.

올바른 방법
  • 먼저 확장자를 보이게 켜기 — 윈도우 탐색기 위쪽 보기 → 표시 → 파일 확장명에 체크. (맥: Finder → 설정 → 고급 → ‘모든 파일 확장자 보기’)
  • 이제 myapp.html 처럼 .html 이 보일 거예요.
  • 오른쪽 클릭 → 이름 바꾸기 → 앞의 myapp 만 지우고 index 로. 점(.html)은 건드리지 마세요.
  • 진짜 이름이 정확히 index.html(점이 1개)인지 확인.

그래서 6단계처럼 이름을 바꾸지 말고 그대로 올린 뒤 주소에 이름을 붙이는 쪽이 더 안전해요.

내가 만든 코드가 HTML 이 아닐 때

올렸는데 화면이 이상하거나, 코드 글자만 보이거나, 안 열린다면 그 코드가 ‘HTML 한 파일’이 아닐 수 있어요. GitHub Pages 는 HTML 파일만 웹페이지로 보여 줘요. 코드 맨 윗줄을 확인해 보세요.

이렇게 시작하면 OK
<!DOCTYPE html><html lang="ko">
이렇게 시작하면 아직 HTML 이 아니에요
import React from "react"function App() { ... }def main(): (파이썬)```jsx / ```python

아래 마법의 문장을 복사해서 AI 채팅에 붙여넣으면 HTML 한 파일로 다시 만들어 줘요. 그 코드로 3단계(Create new file)나 6단계(Upload files)를 똑같이 하면 돼요.

AI에 붙여넣기 지금 만든 걸 HTML 파일 하나로 다시 만들어줘. HTML, CSS, JavaScript를 전부 한 파일에 넣고, 맨 윗줄은 <!DOCTYPE html> 으로 시작하게 해줘. 다른 파일 없이 이 파일 하나만으로 작동해야 해. 파일 이름은 띄어쓰기 없는 영어로 정해줘.
